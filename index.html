Advanced configuration of the Suricata IDS/IPS from the VoIP point of view

Pokročilá detekce a prevence útoků v IP telefonii (SIP/RTP) pomocí vícevláknového enginu Suricata v inline režimu.

Ondřej Kania, Jakub Černík

1. Popis problematiky a současný stav (State of the Art)

Moderní VoIP infrastruktura, postavená nejčastěji na signalizačním protokolu SIP (Session Initiation Protocol) a transportním protokolu RTP (Real-time Transport Protocol), čelí specifickým aplikačním hrozbám. Běžné stavové firewally pracující na 3. a 4. vrstvě modelu ISO/OSI nejsou schopny analyzovat vnitřní strukturu SIP zpráv, což útočníkům umožňuje obcházet základní perimetrovou ochranu.

Hlavní bezpečnostní hrozby ve VoIP

  • SIP Scanning & Enumeration: Mapování aktivních ústředen a platných linek (extensions) nástroji jako SIPVicious.
  • Brute-force útoky na registraci: Automatizované hádání hesel k SIP účtům (záplava požadavků REGISTER s odpověďmi 401 Unauthorized).
  • Toll Fraud: Zneužití kompromitovaných účtů ke generování drahých mezinárodních hovorů.
  • Aplikační DoS / INVITE Flood: Vyčerpání zdrojů pobočkové ústředny (Asterisk/Kamailio) a degradace kvality legitimních hovorů.

Role systému Suricata IDS/IPS

Suricata (vyvíjená organizací OISF) je vysoce výkonný, vícevláknový engine pro detekci (IDS) a aktivní prevenci (IPS) průniků. Oproti klasickým řešením přináší pro VoIP klíčové výhody:

  • Nativní App-Layer parsery pro SIP a RTP: Umožňují přímou kontrolu hlaviček (User-Agent, Method, Status-Code, URI) pomocí tzv. sticky buffers.
  • Inline IPS režim (NFQUEUE): Schopnost zahazovat škodlivé pakety v reálném čase (akce drop) dříve, než dorazí k ústředně.
  • Strukturovaný výstup EVE JSON: Detailní telemetrie vhodná pro integraci se SIEM systémy nebo nástroji typu Fail2Ban.

2. Návrh a řešení úkolu (Task Solution)

2.1 Topologie testovacího prostředí

Testovací prostředí je navrženo jako izolovaná virtuální síť skládající se ze tří uzlů, kde brána se systémem Suricata funguje v inline režimu (IPS) před pobočkovou ústřednou Asterisk:

  • VoIP Server (Oběť): Ubuntu Server + Asterisk PBX (192.168.10.10) + 2 legitimní SIP softphony pro měření kvality hovoru.
  • Suricata IDS/IPS Gateway: Linux router/bridge s aktivním přesměrováním provozu přes iptables NFQUEUE.
  • Útočník (Attacker): Kali Linux s nástroji SIPVicious (svmap, svwar, svcrack) a SIPp.

2.2 Pokročilá konfigurace suricata.yaml

V hlavní konfiguraci byly definovány síťové skupiny pro VoIP, aktivovány aplikační parsery pro SIP a RTP a nastaven strukturovaný výstup eve.json:

vars:
  address-groups:
    HOME_NET: "[192.168.10.0/24]"
    EXTERNAL_NET: "!$HOME_NET"
    VOIP_SERVERS: "[192.168.10.10]"
  port-groups:
    SIP_PORTS: "[5060,5061]"
    RTP_PORTS: "[10000:20000]"

app-layer:
  protocols:
    sip:
      enabled: yes
    rtp:
      enabled: yes

outputs:
  - eve-log:
      enabled: yes
      filetype: regular
      filename: eve.json
      types:
        - alert:
            tagged-packets: yes
        - sip:
            enabled: yes
        - rtp:
            enabled: yes

2.3 Aktivace IPS režimu (NFQUEUE)

Pro přepnutí z pasivního monitorování (IDS) do aktivní blokace (IPS) bylo nastaveno přesměrování paketů z jádra Linuxu do fronty Suricaty:

sudo iptables -I FORWARD -j NFQUEUE --queue-num 0
sudo suricata -c /etc/suricata/suricata.yaml -q 0

2.4 Vlastní detekční a prevenční pravidla (voip-custom.rules)

Byla vytvořena sada pravidel využívajících SIP sticky buffers a prahování (threshold) proti zahlcení a hádání hesel:

# 1. Blokování známých VoIP skenerů (SIPVicious friendly-scanner)
drop sip $EXTERNAL_NET any -> $VOIP_SERVERS $SIP_PORTS (msg:"VOIP-IPS SIPVicious Friendly-Scanner Detected"; sip.user_agent; content:"friendly-scanner"; nocase; sid:1000001; rev:1;)

# 2. Prevence SIP REGISTER Brute-Force (více než 10 odpovědí 401 za 30 s)
drop sip $VOIP_SERVERS $SIP_PORTS -> $EXTERNAL_NET any (msg:"VOIP-IPS SIP REGISTER Brute-Force Attack Detected"; sip.stat_code; content:"401"; threshold: type both, track by_dst, count 10, seconds 30; sid:1000002; rev:1;)

# 3. Ochrana proti SIP INVITE Flood (DoS / Toll Fraud)
drop sip $EXTERNAL_NET any -> $VOIP_SERVERS $SIP_PORTS (msg:"VOIP-IPS High Rate SIP INVITE Flood"; sip.method; content:"INVITE"; threshold: type threshold, track by_src, count 20, seconds 10; sid:1000003; rev:1;)

# 4. Detekce nečekaného RTP provozu mimo vyhrazený rozsah portů
alert rtp any any -> $VOIP_SERVERS !$RTP_PORTS (msg:"VOIP-IDS Unexpected RTP Stream Outside Standard Port Range"; sid:1000004; rev:1;)

3. Praktické testování a naměřené výsledky

Účinnost konfigurace byla ověřena ve třech testovacích scénářích porovnávajících chování ústředny bez ochrany, v režimu IDS a v režimu IPS:

Testovací scénář Použitý nástroj / příkaz Chování bez ochrany Chování se Suricata IPS
1. Skenování SIP ústředny svmap 192.168.10.10 Odhalena verze Asterisku i aktivní port 5060. První paket zahozen (sid:1000001), skener nevidí žádnou odezvu.
2. Brute-force hesla linky svcrack -u 100 -d dict.txt 192.168.10.10 Neomezené zkoušení hesel, vysoké zatížení logů ústředny. Po 10 neúspěšných pokusech (401) aktivován drop (sid:1000002).
3. DoS INVITE Flood sipp -sn uac 192.168.10.10 -r 50 Výrazný nárůst jitteru a ztrátovosti paketů u probíhajícího hovoru. Překročení 20 INVITE / 10 s blokováno, legitimní hovor zůstává stabilní.

4. Závěr a rozdělení práce (Conclusion & Involvement)

Cílem projektu bylo navrhnout, nakonfigurovat a otestovat systém Suricata IDS/IPS se zaměřením na zabezpečení VoIP infrastruktury. Nasazení aplikačních parserů pro SIP a RTP v kombinaci s inline režimem NFQUEUE prokázalo vysokou účinnost proti automatizovaným skenerům, slovníkovým útokům i aplikačnímu zahlcení.

Omezení řešení: Aplikační inspekce SIP hlaviček vyžaduje přístup k nešifrované signalizaci. Při nasazení zabezpečeného protokolu SIPS (SIP over TLS) a SRTP nemůže Suricata číst aplikační vrstvu přímo – v produkčním prostředí je proto nutné ukončit TLS spojení na hraničním prvku (SBC / Kamailio) před inspekcí nebo doplnit detekci o behaviorální analýzu na transportní vrstvě.
